# Documentation

- [Design](design.md) describes the system as designed, and why: its requirements, the trust model, the protocols and formats that anyone checking an election needs, and features the MVP doesn't have yet. The limits in its Known Limits section are limits of the design itself.
- [MVP](mvp.md) describes what this codebase implements: its scope, where it differs from the design, choices the design leaves open, how to run it, and its API and tables. The limits it lists are ones only the MVP has.
- [User stories](user_stories.md), [pages](pages/README.md) and [registration](flows/registration.md) describe the design too.

Implementation work updates mvp.md. design.md only changes when a design decision does.
